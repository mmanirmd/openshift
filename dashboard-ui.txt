# GitHub Copilot Prompt — NPE Platform Portal: Compare Clusters

Act as a senior React/TypeScript frontend engineer, Python FastAPI backend engineer, OpenShift platform engineer, and enterprise UI/UX designer.

## Objective

Implement a new **Compare Clusters** feature in my existing NPE Platform Portal.

Use the attached dashboard image as the primary visual reference.

The feature must allow platform engineers to compare OpenShift clusters by configuration, versions, resource presence, and meaningful configuration differences.

**Important:** Keep the page clean, spacious, readable, and read-only. Do not create an overcrowded dashboard.

## 1. Existing Application

My application uses:

- Frontend: React, TypeScript, Vite
- Backend: Python FastAPI
- Infrastructure: Multiple OpenShift clusters running on VMware vSphere
- Kubernetes/OpenShift APIs for collecting cluster information
- Existing navigation, authentication, shared UI components, and cluster registry

Before implementing anything, inspect the existing project structure, components, routes, API patterns, styling, and authentication.

Reuse existing components and conventions. Do not rebuild the application or change unrelated features.

## 2. Navigation

Add a menu item named **Compare Clusters** under the CONFIGURATION section in the left navigation sidebar.

Preserve the existing sidebar design, including its dark navy background, icons, active navigation highlighting, and spacing.

Page title: **Compare Clusters**

Subtitle: **Compare configuration, versions, and key platform components across OpenShift clusters.**

## 3. Cluster Selection

At the top of the page, create a cluster selection panel.

Requirements:

- Display the available clusters from the backend.
- Allow selecting 2–6 clusters.
- Show cluster name and environment.
- Use checkbox-style cluster selection cards.
- Include a Compare button.
- Allow selecting a baseline cluster.
- Disable comparison until at least two clusters are selected.
- Display loading and error states.

Example cluster names: npe01, npe02, npe03, npe04, npe05, npe06.

Do not hardcode cluster names or environments in production logic.

## 4. Comparison Categories

Below cluster selection, create horizontally arranged category tabs:

1. Overview
2. OpenShift Version
3. Operators
4. Security
5. Networking
6. Storage
7. Node Configuration
8. Observability

Selecting a category should display the relevant comparison results without navigating to another page.

Use the attached image for tab styling.

## 5. Comparison Summary

Display four compact summary cards:

**Matching**
- Number of configuration items that match across selected clusters.

**Different**
- Number of configuration items with different values.

**Missing**
- Number of resources missing from one or more selected clusters.

**Unknown**
- Number of items that could not be retrieved or compared.

Use green, amber, red, and neutral-gray status indicators.

Do not confuse an intentional configuration difference with a critical configuration problem.

## 6. Comparison by Category

Create a clean table with these columns:

| Category | Matching | Different | Missing | Total | Status | Action |
|---|---|---|---|---|---|---|

Include these categories:

- OpenShift Version
- Operators
- Security
- Networking
- Storage
- Node Configuration
- Observability

Each row should show the number of matching, different, missing, and total items.

The **View Details** action should open the selected category's comparison details within the same page.

Do not display large YAML files in the summary table.

## 7. Key Differences

Below the category table, create a section named **Key Differences**.

Display the most important configuration differences as compact, clickable list items.

Each item should contain:

- Resource or configuration name
- Category
- Affected cluster(s)
- Brief description
- Severity or review status

Examples:

- ACS policy baseline missing in npe03
- Gatekeeper operator version mismatch
- Worker MachineConfigPool updating
- ClusterLogForwarder configuration differs
- Default StorageClass differs

Limit the initial display to five items and provide a View All option.

Clicking an item should populate the adjacent Detail View panel.

## 8. Detail View

Create a panel named **Detail View** next to Key Differences, matching the attached dashboard layout.

When a configuration item is selected, display:

- Resource name
- Resource type/category
- Namespace, where applicable
- Comparison status
- Short explanation
- Side-by-side values for selected clusters

Example:

**Gatekeeper Version**

| Cluster | Version |
|---|---|
| npe01 | 3.18.0 |
| npe02 | 3.18.0 |
| npe03 | 3.17.0 |

Highlight differences from the selected baseline.

Add a **View YAML Diff** option for supported Kubernetes resources.

The YAML diff should:

- Compare normalized resource configurations.
- Focus on meaningful `spec` fields and selected configuration metadata.
- Exclude generated metadata such as UID, resourceVersion, managedFields, and timestamps.
- Exclude sensitive information, including Secret contents, credentials, tokens, and private keys.
- Support nested field differences and missing resources.
- Show a clear message when a comparison is unavailable.

For lists representing sets of named resources, normalize ordering where appropriate.

## 9. Configuration Comparison Rules

Support three comparison levels:

**Level 1 — Presence**
- Present
- Missing
- Unknown

**Level 2 — Version and Status**
- Operator versions
- OpenShift version and channel
- Installation status
- MachineConfigPool conditions

**Level 3 — Configuration**
- Compare meaningful fields from selected platform resources.

Prioritize these resource types:

- ClusterVersion
- ClusterOperators
- Operator Subscriptions and CSVs
- MachineConfigPools
- MachineConfigs
- KubeletConfigs
- Gatekeeper ConstraintTemplates and constraints
- SecurityContextConstraints
- ClusterLogForwarders
- IngressControllers
- DNS and Network configuration
- StorageClasses
- Cert-Manager Issuers and ClusterIssuers
- Service Mesh configuration

Where available, include ACS policy configuration through supported APIs.

Do not attempt to compare every Kubernetes resource in the first implementation.

Support expected-difference rules for environment-specific settings such as API endpoints, ingress VIPs, CIDRs, and storage endpoints.

A configuration difference should not automatically be classified as a critical issue.

## 10. Recommendations

In the Detail View, display a small recommendation section when a meaningful difference is detected.

Examples:

- Review a missing security policy.
- Verify whether an older operator version is intentional.
- Investigate an updating or degraded MachineConfigPool.
- Confirm whether a networking difference is expected.

Recommendations must be read-only and advisory.

Do not provide buttons that automatically change cluster configuration.

## 11. FastAPI Backend

Inspect the existing FastAPI architecture and extend it using the established patterns.

Suggested API endpoints:

- `GET /api/compare/clusters`
- `POST /api/compare`
- `GET /api/compare/resources/{resource_id}/diff`

The backend should:

- Reuse the existing cluster registry and authentication.
- Retrieve resource information using Kubernetes/OpenShift APIs.
- Collect information concurrently with reasonable timeouts.
- Normalize resource data before comparison.
- Compare selected clusters against an optional baseline.
- Return structured results for matching, different, missing, and unknown items.
- Cache results where appropriate.
- Handle unavailable clusters and insufficient permissions gracefully.
- Avoid returning credentials or sensitive resource fields.
- Enforce read-only access.

Keep comparison logic separate from API route handlers.

Create reusable normalization and comparison services.

1. Page header

3. Category tabs
4. Four summary cards
5. Comparison by Category table
6. Two-column bottom section:
   - Left: Key Differences
   - Right: Detail View

Keep detailed YAML comparisons hidden until requested.

Use responsive layouts for smaller screens and horizontal scrolling where needed.

Do not add unrelated charts, metrics, or additional dashboards.

- Compare

A production-oriented, read-only **Compare Clusters** feature integrated into my existing NPE Platform Portal.
