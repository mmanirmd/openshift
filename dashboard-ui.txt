3. Block Two — Node Infrastructure CPU & Memory (VM / Node)

Title: 2. Node Infrastructure CPU & Memory (VM / Node)

Description: Aggregated CPU and memory capacity, Kubernetes allocatable resources, and node-level resource utilization across all selected OpenShift clusters.

Include an All Clusters dropdown and Live Data indicator.

Create two equally sized cards side by side.

Left Card — CPU (Nodes / VMs)

Show three metrics:

Total CPU Capacity: 960 vCPUs

Allocatable CPU: 888 vCPUs

Used CPU: 405 vCPUs

Include a donut chart showing CPU usage and remaining capacity.

Use green for CPU utilization and light gray for remaining capacity.

Right Card — Memory (Nodes / VMs)

Show three metrics:

Total Memory Capacity: 3.84 TiB

Allocatable Memory: 3.28 TiB

Used Memory: 2.23 TiB

Include a donut chart showing memory usage and remaining capacity.

Use purple for memory utilization and light gray for remaining capacity.

Technical requirements:

Total capacity represents the combined CPU and memory capacity of OpenShift node VMs.

Allocatable represents resources available to Kubernetes after node reservations.

Used represents current node-level resource consumption.

Use Kubernetes/OpenShift node capacity and allocatable values as the source of truth for those metrics.

Do not assume vSphere hypervisor utilization is identical to Kubernetes node utilization.

Calculate utilization percentages consistently against the explicitly labeled denominator.

Remaining allocatable capacity = allocatable minus measured usage, where the measurements are comparable.

All numerical values are illustrative mock data, not live measurements.

Important: Do not display individual node lists or tables in this block.

4. Block Three — Kubernetes Workload CPU & Memory (Pods)

Title: 3. Kubernetes Workload CPU & Memory (Pods)

Description: Aggregated CPU and memory requests, limits, and actual resource usage for workloads across selected OpenShift clusters.

Include an All Clusters dropdown and Live Data indicator.

Create two equally sized cards side by side.

Left Card — CPU (Pods)

Display:

CPU Requests: 612 vCPUs

CPU Limits: 924 vCPUs

Current CPU Usage: 282 vCPUs

Show requests, limits, and usage as separate metrics.

Add a donut chart comparing actual CPU usage against the total allocatable CPU capacity of 888 vCPUs.

Use green for used CPU and light gray for remaining allocatable capacity.

Show utilization percentages for requests, limits, and usage relative to allocatable CPU.

Right Card — Memory (Pods)

Display:

Memory Requests: 1.88 TiB

Memory Limits: 2.96 TiB

Current Memory Usage: 980 GiB

Add a donut chart comparing actual memory usage against the total allocatable memory capacity of 3.28 TiB.

Use purple for used memory and light gray for remaining allocatable capacity.

Show percentages relative to allocatable memory.

Technical requirements:

Requests represent resources requested by Kubernetes workloads.

Limits represent maximum configured container resource limits.

Actual usage represents current workload consumption.

Limits may exceed allocatable capacity because Kubernetes permits overcommitment.

Never treat CPU or memory limits as physical available capacity.

Clearly distinguish node-level usage from pod-level usage.

Do not include a Total Pods card.

Do not include pod lists, workload tables, or individual cluster tables.


. Key Information Panel

At the bottom, add a subtle light-blue informational panel titled Key Information.

Explain briefly:

Node infrastructure metrics show VM/node capacity, allocatable resources, and actual node utilization.

Kubernetes workload metrics show pod requests, limits, and actual usage.

Requests and limits are not the same as actual consumption.

CPU and memory limits can exceed allocatable resources because of overcommitment.

Historical trends and detailed analysis are available in Reports.

7. Layout Order — Mandatory

The dashboard must contain exactly these three main sections, stacked vertically:

Block 1: Cluster Status — four summary cards only.

Block 2: Node Infrastructure CPU & Memory (VM / Node) — two cards for CPU and memory, each showing capacity, allocatable, and usage.

Block 3: Kubernetes Workload CPU & Memory (Pods) — two cards for CPU and memory, each showing requests, limits, and actual usage.

Finish with the Key Information panel.

Do not merge the node and workload sections. Do not add cluster, node, or pod tables to the main overview.
